# The deliberate mess in the synthetic data

All three inputs are generated by `reconciler/generate.py` (seed in `config.py`). Nothing is real.
Each item below is on purpose, and a test or a report section depends on it.

| Mess | Where | What a careless pipeline does | What this one does |
|---|---|---|---|
| Seat reassigned mid-month | `S-LB-12` on 2026-04-17, `S-CO-17` on 2026-05-12 (`events/`) | Counts two users, so two seats | One seat, split by day, one seat price in total |
| Invoice file imported twice | `invoices/invoice_LB_2026-04 (1).csv`, same bytes as the original | Doubles April for Lebanon | Recorded in `raw_files.duplicate_of`, adds no rows |
| Usage report a month late | `usage/usage_CO_2026-08.csv`, due 2026-09-05, received 2026-10-06 | Treats Colombian seats as unused | Ignored before its arrival, so every seat-month is `unknown` |
| Late report changes the answer | `CO-033` silent May to July, active in August | Reclaims a seat from someone who came back | Candidate on the early data, not a candidate once August arrives |
| Late onboarding | Kenya assigns 30 seats on 2026-03-04, usage starts in July | Calls Kenya the worst office and reclaims seats | Detects the start month, holds the seats back |
| Seats billed but never assigned | 2 in Lebanon, 3 in Colombia: the invoice bills more seats than the log mentions | Ignores them or fails to reconcile | Shown as paid, nobody assigned |
| A user missing from a report | `CO-015` absent from the Colombia July report | Reads absence as zero use | `unknown` |
| Dirty ids | Colombia June report: lower case with a trailing space | Users fail to join | Trimmed and upper-cased in staging |
| A repeated row | `KE-005` twice in the Kenya July report | Double counts the user | First row kept |
| Unordered log | `events/assignment_events_*.csv` is shuffled | Wrong holder at the end | Ordered by date and event id inside the SQL |
